### A7 stream / group 的上游语义（用户查证，已确认前一 session 说反了）

`MemoryVLA` 上游 `vla/datasets/datasets.py:268-313`：

- `group`：一条 T 帧 episode → `tf.random.shuffle(range(T))[:16]` → `tf.sort`
  ⇒ **跨整条 episode 稀疏取 16 帧、按时间排序**（T<16 时末帧 pad）
- `stream`：完全不采样，T 帧原样保留

对照我们的移植：

| | 我们的实现 | 是否忠实 |
|---|---|---|
| `stream` | episode 有序采样器逐帧走，bank 跨 forward 累积、tome 压到 16 槽 | ✅ 忠实 |
| `group` | **没有稀疏采样器**，喂进去仍是连续帧 ⇒ 退化成「batch 内前 N 个连续帧」 | ❌ **不忠实** |

`memory_bank.py` 里「`group` 每次 forward 清 bank」的**消费端**逻辑是对的
（它正是为「一个 batch = 一条 episode 的 16 帧摘要」设计的），
缺的是**生产端**（`use_optim_group_sample=True` 对应的组采样器）。

⇒ **移植缺陷**：`dataloader_type="group"` 目前不是上游语义。
两个出路：实现稀疏组采样器，或在装配期直接拒绝 `group` 并说明原因。

行为完全不变），本地脚本传 `$(basename $RUN)`。**已被覆盖的数据回不来。**
